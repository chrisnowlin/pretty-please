KEY FINDINGS
============

ARCHITECTURE OVERVIEW
- Backend: FastAPI (Python) - Port 8000
- Frontend: React/TypeScript with Vite - Port 5173
- Vector Database: ChromaDB (persistent, local-first)
- Embeddings: Jina v4 (2048-dim, Apple Silicon optimized)
- OCR Engine: DeepseekOCR with GUNDAM mode (dynamic resolution)
- LLM: Qwen generator for lesson planning
- Database: SQLAlchemy with SQLite

FRONTEND/BACKEND SEPARATION
- Clean separation with relative API URLs (/api)
- WebSocket for real-time progress (/ws/progress/{task_id})
- Frontend dist mounted at / for production serving
- CORS enabled for development flexibility
- Vite dev server proxies API calls in development

KEY MODULES
Backend:
  - api/: FastAPI application + models + task management (1636 lines + 55k)
  - embeddings/: Jina v4 implementation with config presets
  - ingestion/: Document processing, OCR, chunking, semantic regions
  - storage/: ChromaDB vector store abstraction
  - retrieval/: Educational retriever, reranker
  - generation/: Qwen LLM, lesson planner, PDF exporter
  - database/: SQLAlchemy ORM, lesson persistence
  - monitoring/: Metrics collection
  - workers/: Optional RQ distributed processing

Frontend:
  - pages/: 6 main page components (Search, Ingest, Collections, Chat, Lessons, Settings)
  - components/: Reusable UI components organized by feature
  - services/: APIClient class with full API wrapper
  - contexts/: Theme management
  - hooks/: Custom React hooks
  - styles/: Theme configuration

RAG PIPELINE FLOW
1. Document Upload (Frontend)
   ├─ POST /api/ingest/upload
   └─ WebSocket /ws/progress/{task_id}

2. OCR Ingestion (DeepseekOCR + GUNDAM)
   ├─ Dynamic resolution (640×640 or 1024×1024)
   ├─ Grounding (bounding boxes)
   ├─ Compression (optical)
   └─ Attention: SDPA on MPS

3. Document Processing
   ├─ Markdown parsing
   ├─ Metadata extraction
   ├─ Thumbnail generation
   └─ Image extraction

4. Semantic Chunking
   ├─ Split by boundaries (1000 chars)
   ├─ Overlap for context (200 chars)
   └─ Filter empty chunks

5. Embedding Generation
   ├─ Batch processing (32 tokens)
   ├─ 2048-dimensional vectors
   └─ Task-specific optimization (retrieval.passage)

6. Vector Storage
   ├─ ChromaDB collection creation
   ├─ Metadata attachment
   └─ Persistent disk storage (.chroma_db/)

7. Artifact Organization
   ├─ Original documents
   ├─ Extracted images
   └─ Thumbnails

CONFIGURATION SYSTEM
Runtime Configs (./data/):
- embedding_config.json: Task, dimensions, late_chunking, format
- ocr_config.json: Resolution mode, grounding, compression, batch size
- collection_configs/: Per-collection settings

Configuration Presets:
Embeddings:
  - for_query: Fast single-shot (1024-dim)
  - for_documents: Context preservation (1024-dim with late chunking)
  - fast: 4× faster (512-dim)
  - storage_optimized: Binary format (8× smaller)

OCR:
  - deepseek_tiny: Fastest (512×512)
  - deepseek_small: Balanced (640×640)
  - deepseek_balanced: Default (1024×1024)
  - deepseek_high_quality: High fidelity (1280×1280)
  - deepseek_gundam: Dynamic multi-resolution
  - deepseek_production: vLLM acceleration (GPU)
